# 能力缺口与权限契约

**为什么 gstack 编排团队必须与领域智能体协作 —— 而且永远不能凌驾其上。**

`gstack-tutorial-2` 的一部分。简版见 [`../TUTORIAL.zh.md`](../TUTORIAL.zh.md) §0.4。

---

## 1. 一句话主张

5 个 gstack 角色（AI CEO、AI PM、AI 工程师、AI QC、AI DevOps）是**流程专家、
领域通才**。它们懂得拆解、排序、审计、发布；但不懂半导体物理、EDA 工具的语义，
也不知道一道签核门究竟证明了什么。两个领域智能体（AI GDS-Architect、
资深模拟 IC 设计架构师）正好相反：它们掌握领域判断与流程语义，不关心迭代节奏
与打包。**正确的团队设计不是"5 加 2"，而是一套双钥匙机制：流程权限归 gstack，
物理权限归领域智能体；两者冲突时，物理权限胜出。**

---

## 2. 每一层真正知道什么

### 第 1 层 —— gstack 编排

| 擅长 | 不懂 |
|---|---|
| 把目标拆成可归档、可派发的任务 | 目标工艺节点该用哪个 PDK 库 |
| 挑战范围与定位 | 某套 DRC 规则是否覆盖了金属密度 |
| 维护决策的审计轨迹 | LVS 可能是循环论证 |
| 产出发布物与版本标签 | GDS 怎样才能做到字节级可复现 |
| 只报告不改（QA 纪律） | "网表匹配"**没有**证明什么 |

### 第 2 层 —— 领域智能体

| 擅长 | 不负责 |
|---|---|
| RTL→GDS 流程语义及其失效模式 | 迭代节奏、任务拆解 |
| 每道签核门证明了什么、没证明什么 | 发布机制、打包 |
| 构造非循环验证 | 定位与商业叙事（可否决，不主笔） |
| 确定性：哈希种子、冻结时间戳、RNG | 议题追踪的规范 |
| 模拟：拓扑、sizing、仿真、版图意图 | — |

### 第 3 层 —— 工具链

中立裁判。它不谈判。一道门要么凭其日志通过，要么不通过。正因如此，第 3 层是
唯一有权裁决第 1 层与第 2 层争执的一方。

## 3. 权限契约（RACI）

R = 执行，A = 唯一担责，C = 被咨询，I = 被告知，**X = 无权决定**

| 决策事项 | AI CEO | AI PM | AI 工程师 | AI QC | AI DevOps | GDS 智能体 | 模拟智能体 | 人类 |
|---|---|---|---|---|---|---|---|---|
| 范围与阶段划分 | A | R | C | I | I | C | C | 批准 |
| 任务拆解（W1–W9） | C | A/R | C | I | I | C | — | I |
| PDK / 标准单元库选择 | X | X | X | X | X | **A** | C | 批准 |
| 工具版本锁定 | X | 记录 | X | X | 记录 | **A** | **A** | I |
| 门通过判据 | X | X | X | 执行 | X | **A** | **A** | I |
| DRC 违例豁免 | X | X | X | X | X | **A** | C | **签字** |
| LVS 失配解读 | X | X | 报告 | 报告 | X | **A** | C | I |
| 确定性契约 | X | 记录 | X | X | 记录 | **A** | — | I |
| 发布内容与版本号 | C | C | I | C | **A** | C | C | 批准 |
| 路线图 / 对外文案 | 起草 | 起草 | X | X | 起草 | **审核** | **审核** | 批准 |
| 任何含物理数字的表述 | X | X | X | X | X | **A** | **A** | I |

先读 **X** 那一列。那才是整张表的重点。

## 4. 三条否决规则

1. **领域否决优先于流程便利。**
   领域智能体说某步不安全，那一步就不做 —— 无论计划、待办清单还是进度表怎么写。

2. **门的结果不是事实，直到领域智能体读过日志 —— 而不只是状态行。**
   `PASS`、`Circuits match uniquely.`、`DRC clean` 都只是字符串，日志才是证据。
   AI QC 只有在领域智能体**读过日志之后**，才被允许**报告**状态。

3. **绝不为让构建通过而放宽检查。**
   门失败时，要么产物错了，要么门错了。领域智能体必须书面说明是哪一种。
   任何人不许静默放宽容差、放大窗口，或从规则档里删规则。

## 5. 升级处置流程（实例）

**现象。** `/qa-only` 报告门 7B-1R2 PASS，日志含 `Circuits match uniquely.`

**幼稚反应。** 接受 → 关闭条目 → 发布。

**正确反应。**

| 步骤 | 主体 | 动作 |
|---|---|---|
| 1 | AI QC | 报告状态，**并**确认参考网表的来源 |
| 2 | AI GDS-Architect | 读日志。判定：参考源是流片前从**活的** P&R 数据库导出的，还是从 GDS 本身提取的？ |
| 3 | — | 若来自 GDS：该检查是循环论证。状态不是 PASS，是 **VOID（作废）** |
| 4 | 领域智能体 | 书面说明错的到底是产物还是门 |
| 5 | AI PM | 把发现立为任务项；不得改写报告措辞 |
| 6 | 人类 | 签字 |

让这套流程成立的一句话：

> **"PASS" 只是一个字符串。日志才是证据。**

## 6. 五种反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 让 AI 工程师选 PDK 库 | 它优化的是"存在某个库"，不是电气适配 | GDS 智能体决定，人类批准 |
| 让 AI QC 认证自己重跑过的门 | 等于拆除抵御确认偏误的唯一防线 | 领域智能体读日志 → QC 报告 → 人类签字 |
| 让 AI CEO 撰写物理论断 | 产出自信、合理、但错误的数字 | CEO 起草 → 领域智能体审核 → 人类批准 |
| "放宽容差吧，进度落后了" | 摧毁门链存在的唯一理由 | 绝不。改为升级处置 |
| 把领域智能体当评审员 | 浪费。它们是生产者，不是评论者 | 给它们任务项，附产物与判定门 |

## 7. 让渡条款（可直接复制）

### 中文

```text
需征询领域智能体。在你敲定任何涉及 DRC、LVS、提取、确定性或 PDK 规则的表述之前，
先将该具体论断交给领域智能体（数字方向交给 AI GDS-Architect，模拟方向交给
资深模拟 IC 设计架构师），并逐字引用其答复。

若领域智能体与你的结论冲突，以领域智能体为准。不要自行裁决 ——
把两方陈述并列提交给人类裁决。
```

### English

```text
CONSULT REQUIRED. Before you finalise any statement about DRC, LVS, extraction,
determinism, or PDK rules, hand that specific claim to the domain agent
(AI GDS-Architect for digital, Senior Analog IC Architect for analog) and quote
its answer verbatim.

If the domain agent contradicts you, the domain agent wins. Do not resolve the
conflict yourself — escalate to the human with both statements side by side.
```

把这一段附加到本教程中**每一个** `/plan-ceo-review`、`/spec`、
`/plan-eng-review`、`/qa-only`、`/ship` 提示词上。

## 8. 领域智能体凭什么可信

不是宣称，是证据。

| 证据 | 出处 |
|---|---|
| 含非循环 LVS（7B-1R2）的门链 | 教程 §5.3；已验证运行日志 |
| 确定性 GDS，字节级可复现 | 教程 §6.3；`PYTHONHASHSEED=0` + 冻结 GDS 时间戳 |
| 微混沌混合器，正李雅普诺夫指数（2002） | *Int. J. Numer. Meth. Fluids* |
| KAM 环面破裂 / FTLE 表征（2003） | *J. Micromech. Microeng.*；ASME IMECE 41389 |
| **非线性动力学分析**，与何志明教授合著（2007） | *J. Fluid Mech.* **575**, 425–448 |
| 混沌混合器进入 CTC 芯片 —— *Angewandte* 封面（2011） | *Angew. Chem. Int. Ed.* **50**(13), 3084–3088 |
| 预测 vs 实测：Ca\* 0.043 vs 0.04 ± 0.006（2019） | 二自由度非线性 m–c–k 模型 |
| 预测 vs 实测：127.8 W vs 127.4 W（0.29%） | 教程 §8.2，并声明 FM 独立取得 |

贯穿其中的模式是：**方法必须拿实测校验，且主动写明可被证伪的前提。**
这是编排层被要求尊重、而非取代的标准。

## 9. 把这套模式推广出去

这份契约并不只适用于半导体。任何"错误产物代价高昂、而通才无法察觉"的领域，
都需要同样的双钥匙结构：

1. 明确列出编排层**无权判断**的事项，写成显式的 X 列。
2. 给领域智能体**产物 + 判定门**，而不是顾问角色。
3. 认证之前要求**读日志**，而不是报状态。
4. 把**放宽检查**定为唯一不可饶恕的动作。
5. **人类签名**只用于豁免事项。

如果你的领域智能体产出的文件没有任何一道门去检验，它是在写作业，不是在做工程。
